把旧记忆重新带回上下文

真正的关键不是保存了多少历史，而是启动新任务时有没有把旧记忆重新塞回 system prompt。

看 GitHub 行号 
 199 def run_agent_plus(task, use_plan=False):
 200     memory = load_memory()
 201     system_prompt = (
 202         "You are a helpful assistant that can interact with the system. Be concise."
 203     )
 204     if memory:
 205         system_prompt += f"\n\nPrevious context:\n{memory}"

演示 Agent 如何把一次执行结果写进记忆文件，并在下一次运行时直接把这段历史带回来。

演示命令

python agent/02-memory/agent-memory.py "创建 launch-note.txt，内容是 Agent Memory Demo"
python agent/02-memory/agent-memory.py "不重新读文件，只根据记忆说明你上一次完成了什么任务"
  • 第一次运行结束后，打开 `agent_memory.md`，确认任务和结果已经被追加进去。
  • 第二次运行即使不重新读文件，也能基于刚才的历史说明“上一次做了什么”。
  • 最后指出真正关键的不是 `--plan`，而是 `load_memory()` 和 `save_memory()` 形成了闭环。

Takeaway

这一讲会看懂什么

  • 能说清 Memory 至少包含写入、读取、回放三步。
  • 能看懂 `load_memory()`、`save_memory()` 和 `run_agent_plus()` 是怎么串起来的。
  • 知道规划是可选增强，但这一讲真正的主线是持久记忆。

Share Track

分享只讲这 3 件事

  • 最小 Memory 不需要向量库，先把“写进文件”和“下次读回”这条链路跑通就够了。
  • 真正让 Agent 记住过去的，不是文件本身，而是把历史重新注入了 system prompt。
  • 规划可以以后再展开，但没有 Memory，Agent 每次启动都像失忆重来。

Misread

容易误解

  • 只写入不读取，不算真正的 Memory，只是留下了一份日志。
  • 历史内容回放过多，后面很快又会碰到上下文膨胀。
  • 把错误结果写进记忆后，下一轮会把污染一起带回来。

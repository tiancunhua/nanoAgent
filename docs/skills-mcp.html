Scenario

什么时候会用到

团队有自己的代码规范、有内部 API、还希望不同项目用不同能力，但又不愿意把这些都硬写进脚本里。能力外置，就是把这些差异从代码里抽到项目目录中。

 226 def load_skills():
 227     skills = []
 228     if not os.path.exists(SKILLS_DIR):
 229         return []
 230     try:
 231         # 这里先只扫描 Skill 文件，不急着把完整内容都交给大模型。
 232         # 后面会分成“摘要注册”和“命中后加载详情”两个阶段写入 prompt。
 233         skill_files = sorted(Path(SKILLS_DIR).glob("*/SKILL.md")) + sorted(
 234             Path(SKILLS_DIR).glob("*.md")
 235         )
 236         for skill_file in skill_files:
 237             skills.append(parse_markdown_skill(skill_file))
 238         return skills
 239     except:
 240         return []

 243 def parse_markdown_skill(path):
 244     content = path.read_text(encoding="utf-8")
 245     metadata = {}
 246     body = content
 247     # frontmatter 是给路由用的轻量信息；body 才是命中后加载的完整 Skill。
 248     if content.startswith("---\n"):
 249         end = content.find("\n---", 4)
 250         if end != -1:
 251             frontmatter = content[4:end].strip()
 252             body = content[end + 4 :].strip()
 253             for line in frontmatter.splitlines():
 254                 if ":" not in line:
 255                     continue
 256                 key, value = line.split(":", 1)
 257                 metadata[key.strip()] = value.strip()
 258     name = metadata.get(
 259         "name", path.parent.name if path.name == "SKILL.md" else path.stem
 260     )
 261     triggers = [
 262         trigger.strip().lower()
 263         for trigger in metadata.get("triggers", "").split(",")
 264         if trigger.strip()
 265     ]
 266     return {
 267         "name": name,
 268         "description": metadata.get("description", ""),
 269         "when_to_use": metadata.get("when_to_use", ""),
 270         "triggers": triggers,
 271         "path": str(path),
 272         "content": body,
 273     }

 276 def format_skill_summary_for_prompt(skill):
 277     # 第一阶段：只把 Skill Registry 放进 prompt。
 278     # 大模型先看到有哪些 Skill、何时使用、详情文件在哪里，但还看不到完整手册。
 279     lines = [f"- {skill['name']}: {skill.get('description', '')}"]
 280     when_to_use = skill.get("when_to_use")
 281     if when_to_use:
 282         lines.append(f"  When to use: {when_to_use}")
 283     if skill.get("triggers"):
 284         lines.append(f"  Triggers: {', '.join(skill['triggers'])}")
 285     lines.append(f"  Detail file: {skill['path']}")
 286     return "\n".join(lines)

 289 def skill_matches_task(skill, task):
 290     # 演示里用明确的字符串匹配模拟“Skill 路由”。
 291     # 真实框架也可以让模型根据 Registry 判断是否需要打开某个 Skill。
 292     task_lower = task.lower()
 293     if skill["name"].lower() in task_lower:
 294         return True
 295     return any(trigger in task_lower for trigger in skill.get("triggers", []))
 296
 297
 298 def format_skill_detail_for_prompt(skill):
 299     # 第二阶段：任务命中后，才把完整 SKILL.md 正文追加到 prompt。
 300     # 这样上下文不会被所有 Skill 挤满，也能清楚观察“渐进式加载”发生了。
 301     return f"## {skill['name']}\nSource: {skill['path']}\n\n{skill['content']}"

 304 def load_mcp_tools():
 305     if not os.path.exists(MCP_CONFIG):
 306         return []
 307     try:
 308         with open(MCP_CONFIG, "r") as f:
 309             config = json.load(f)
 310             mcp_tools = []
 311             for server_name, server_config in config.get("mcpServers", {}).items():
 312                 if server_config.get("disabled", False):
 313                     continue
 314                 for tool in server_config.get("tools", []):
 315                     mcp_tools.append({"type": "function", "function": tool})
 316             return mcp_tools
 317     except:
 318         return []

进入上下文与工具列表的方式

关键在注入时机：Skill Registry 先进入 prompt，命中的 Skill 详情随后进入 prompt，MCP 工具进入 all_tools。

 357 def run_agent_with_external_capabilities(task):
 358     rule_count = count_rule_files()
 359     rules = load_rules()
 360     skills = load_skills()
 361     # matched_skills 表示“本轮任务真正需要展开的 Skill”。
 362     # 没命中的 Skill 只保留摘要；命中的 Skill 才会加载完整 Markdown。
 363     matched_skills = [skill for skill in skills if skill_matches_task(skill, task)]
 364     mcp_tools = load_mcp_tools()
 365     all_tools = base_tools + mcp_tools
 366     context_parts = [
 367         "You are a helpful assistant that can interact with the system. Be concise."
 368     ]
 369     if rules:
 370         context_parts.append(f"\n# Rules\n{rules}")
 371         print(f"[Rules] Loaded {rule_count} rule files")
 372     if skills:
 373         # 先注册 Skill 摘要，相当于给模型一张能力目录。
 374         context_parts.append(
 375             f"\n# Skill Registry\n"
 376             + "\n".join(format_skill_summary_for_prompt(skill) for skill in skills)
 377         )
 378         skill_names = [skill["name"] for skill in skills]
 379         print(
 380             f"[Skills] Registered {len(skills)} skill summaries: "
 381             f"{', '.join(skill_names)}"
 382         )
 383     if matched_skills:
 384         # 再按本轮任务命中的结果，追加完整 Skill 详情。
 385         context_parts.append(
 386             f"\n# Loaded Skill Details\n"
 387             + "\n\n".join(
 388                 format_skill_detail_for_prompt(skill) for skill in matched_skills
 389             )
 390         )
 391         skill_names = [skill["name"] for skill in matched_skills]
 392         print(
 393             f"[Skills] Progressive load {len(matched_skills)} skill details: "
 394             f"{', '.join(skill_names)}"
 395         )
 396     if mcp_tools:
 397         tool_names = [tool["function"]["name"] for tool in mcp_tools]
 398         print(f"[MCP] Loaded {len(mcp_tools)} MCP tools: {', '.join(tool_names)}")
 399     messages = [{"role": "system", "content": "\n".join(context_parts)}]

---
name: todo_prioritizer
description: 给候选修复项排序：安全风险第一，阻塞运行第二，核心功能第三，文档或示例最后；如果只允许输出 3 项，舍弃文档或示例项，并保持输出简洁。
when_to_use: 当任务要求整理修复顺序、挑选优先级或从多个候选问题中选出下一步行动时使用。
triggers: todo_prioritizer, 修复顺序, 优先级, 候选修复项, 最该先修
---

# Todo Prioritizer

## Use When

当任务要求整理修复顺序、挑选优先级，或从多个候选问题中选出下一步行动时使用。

## Priority Order

1. 安全风险
2. 阻塞运行
3. 核心功能
4. 文档或示例

## Steps

1. 先识别每个候选项属于安全风险、阻塞运行、核心功能、文档示例中的哪一类。
2. 按安全风险、阻塞运行、核心功能、文档示例的顺序排序。
3. 如果题目要求最多 3 项，只输出前三项。
4. 每项用“优先级 - 类别 - 事项”的短格式。
5. 最后用一句话说明被舍弃项为什么靠后。

## Output Example

```text
1. 优先级 - 安全风险 - 删除用户接口缺少权限校验
2. 优先级 - 阻塞运行 - 应用启动时报错无法运行
3. 优先级 - 核心功能 - 搜索结果分页偶尔重复

舍弃项：README 示例命令有错别字（文档或示例类，优先级最低）。
```

  • 第一屏先看三类日志：[Rules] Loaded ...、[Skills] Registered 1 skill summaries: todo_prioritizer、[MCP] Loaded ...。
  • 第一条命令观察 [Tool] project_guide(...)，用真实工具调用证明 MCP 已进入 tools。
  • 第二条命令观察回答是否遵守 .agent/rules/demo-style.md 的格式要求，用输出格式证明 Rule 生效。
  • 第三条命令会额外出现 [Skills] Progressive load 1 skill details: todo_prioritizer，证明命中任务后才加载完整 Markdown Skill。

  • DEFAULT_MAX_ITERATIONS = 10 只是为了保证现场演示有足够轮次完成工具调用与结论生成。

Takeaway

这一讲会看懂什么

  • 知道 Skill 负责补充知识，Rule 负责约束行为，MCP 负责接入外部工具。
  • 能识别 Rules、Skills、MCP 各自的加载来源，以及它们如何拼装进上下文与工具列表。
  • 理解工程化 Agent 的关键不在于继续堆内置逻辑，而在于能力与约束的外置。

Key Points

三个核心要点

  • 最小 Rule 用来约束输出行为，最小 Skill 用来补充任务知识，最小 MCP 用来扩展可调用工具。
  • Rules 与 Skills 最终进入 prompt，MCP 最终进入 tools，注入位置不同，作用也不同。
  • DEFAULT_MAX_ITERATIONS = 10 是演示友好值，能避免复杂搜索在结论前过早中断。

Pitfalls

容易误解

  • 将全部约束堆入 Rule，会模糊职责边界，模型也更难稳定执行。
  • Skills 过多会稀释上下文，MCP 工具过多会降低模型的工具选择准确率。
  • 迭代次数调高会改善演示完整度，但也会增加 token 成本与执行时间。
  • 规则、技能、工具描述互相冲突时，模型表现会显著不稳定。

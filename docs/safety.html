  98 def truncate_output(text):
  99     """超长输出截断，保留首尾"""
 100     if len(text) <= MAX_OUTPUT_LENGTH:
 101         return text
 102     half = MAX_OUTPUT_LENGTH // 2
 103     return (

 105         + f"\n\n... [输出过长，已截断。原始 {len(text)} 字符，保留首尾各 {half} 字符] ...\n\n"

安全版 execute_bash

三道防线是如何串起来的，这段函数最清楚。

看 GitHub 行号 
 162 def execute_bash(command):
 163     # 防线 1: 黑名单检查
 164     dangerous, pattern = is_dangerous(command)
 165     if dangerous:
 166         msg = f"🚫 命令被拦截（匹配危险模式: {pattern}）: {command}"
 167         print(f"  {msg}")
 168         return msg
 169
 170     # 防线 2: 用户确认
 171     if not ask_user_confirmation("execute_bash", {"command": command}):
 172         return "用户跳过了此命令。"
 173
 174     # 执行
 175     try:
 176         result = subprocess.run(
 177             command, shell=True, capture_output=True, text=True, timeout=30
 178         )
 179         output = result.stdout + result.stderr
 180     except subprocess.TimeoutExpired:
 181         output = "Error: 命令执行超时（30秒）"
 182     except Exception as e:
 183         output = f"Error: {str(e)}"
 184
 185     # 防线 3: 输出截断
 186     return truncate_output(output)

Talk Track

讲课只讲这 3 件事

  • 黑名单负责挡住已知高危动作，人工确认负责最后边界。
  • 输出截断既是安全问题，也是稳定性问题。
  • 真正可用的 Agent 一定要允许用户拒绝某一步。

Pitfalls

容易踩坑

  • 只靠黑名单是不够的，绕过方式永远存在。
  • 所有动作都确认会严重伤体验，要做分级策略。
  • `--auto` 只能在你完全信任的隔离环境里用。

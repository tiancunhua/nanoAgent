01 / AGENT FIRST LESSON

从“会回答”到“会做事”

Agent 没有神秘魔法。它只是给 LLM 接上工具，再让它反复观察结果、决定下一步。

01 · 工具说明书

这里不是在执行工具，而是在告诉 LLM：“你可以做什么，调用时要给什么参数。”

读代码时只看一条主线： LLM 根据目标选择工具，Python 执行工具，结果写回 messages，LLM 再根据新信息决定下一步。 这四步不断重复，直到模型不再发起工具调用。教学代码刻意保持最小，真实系统还会加入权限、超时、路径隔离和人工确认。

02 / SKILL

Skill：给聪明新员工一份工作手册

模型有通用能力，但不知道你公司的流程、标准和坑。Skill 把人的经验变成 Agent 可以反复使用的操作说明。

没有 Skill

“帮我发布这次版本。”

“当然。你可以先运行测试，然后提交代码……”

礼貌地告诉你怎么做。

→
装上发布 Skill

“帮我发布这次版本。”

  • 检查测试与变更范围
  • 扫描敏感信息
  • 生成发布说明并等待确认

按照团队 SOP 把事做稳。

SKILL.MD · 四块就够

一份好 Skill 写清楚什么？

触发器要具体。

写出任务类型和用户常用说法，让 Agent 知道什么时候应该加载这份手册。

SKILL.md● ● ●
---
name: release-check
description: 发布前检查。
  Use when 用户说“发布、上线、推送”。
---

# Workflow
1. 运行测试
2. 检查变更范围
3. 生成发布摘要

# Guardrails
- 发现密钥立即停止
- 推送前必须获得确认

# Output
返回：检查结果、风险、下一步

OPEN DISCUSSION

把你熟悉的一件事，教给 Agent

想一个你每周都会重复的任务。不要先想“AI 能不能做”，先写下你会怎样教一个聪明的新同事。

  1. 01

    什么时候触发？用户会怎么提出这个任务？

  2. 02

    标准步骤是什么？先做什么，再做什么？

  3. 03

    哪里最容易出错？什么时候必须停下来问人？

  4. 04

    完成长什么样？文件、消息还是一份报告？

TAKEAWAY

今天只带走三句话

01

LLM 会生成，但它本身不会操作真实世界。

02

Agent = LLM + 工具 + 循环，把回答变成行动。

03

Skill 把人的经验写成工作手册，让行动稳定、可复用。

别把 Agent 想成一个无所不知的人。

把它当作一个聪明、肯干、
但需要明确工具与方法的新同事。

06. 上下文压缩

本讲跳过理论铺垫，专注于一个核心问题：长任务中 Agent 为何会被自身历史拖垮，以及压缩如何缓解。

Scenario

什么时候会用到

交给 Agent 一个跨几十轮的长任务，会发现它越走越慢、回答越来越含糊——背后是 messages 一直在膨胀，前面所有工具调用结果都被一次次带着走，最终撑爆 context window。

上下文压缩函数

这是上下文压缩的核心实现：将旧历史折叠为摘要，保留当前工作现场。

 125 COMPACT_THRESHOLD = 8  # 演示用低阈值：几轮工具调用后就能看到压缩
 126 KEEP_RECENT = 4  # 至少保留最近几条消息；遇到 tool 调用组会向前扩展

 129 def message_role(message):
 130     if isinstance(message, dict):
 131         return message.get("role", "unknown")
 132     return getattr(message, "role", "unknown")
 133

 135 def find_recent_start(messages):
 136     start = max(1, len(messages) - KEEP_RECENT)
 137     # 不要从 tool 消息中间切开；tool 必须紧跟触发它的 assistant tool_call。
 138     while start > 1 and message_role(messages[start]) == "tool":
 139         start -= 1
 140     return start
 141
 142
 143 def compact_messages(messages):
 144     """
 145     当 messages 过长时，把旧消息压缩成一段摘要。
 146
 147     压缩前: [system, msg1, msg2, msg3, msg4, msg5, msg6, msg7, msg8]
 148     压缩后: [system, summary_of(msg1~msg4), ack, msg5, msg6, msg7, msg8]
 149     """
 150     if len(messages) <= COMPACT_THRESHOLD:
 151         return messages  # 没超阈值，不压缩
 152
 153     print(
 154         f"\n[Compact] messages 数量 ({len(messages)}) 超过阈值 ({COMPACT_THRESHOLD})，开始压缩..."
 155     )
 156
 157     system_msg = messages[0]  # system prompt 永远保留
 158     recent_start = find_recent_start(messages)
 159     old_messages = messages[1:recent_start]  # 需要被压缩的旧消息
 160     recent_messages = messages[recent_start:]  # 最近的消息保留原样
 161
 162     # 把旧消息拼成文本，交给 LLM 做摘要
 163     old_text = ""
 164     for msg in old_messages:
 165         role = message_role(msg)
 166         content = (
 167             msg.get("content", "")
 168             if isinstance(msg, dict)
 169             else getattr(msg, "content", "")
 170         )
 171         if content:
 172             old_text += f"[{role}]: {content}\n"
 173
 174     # 调用 LLM 生成摘要
 175     summary_response = client.chat.completions.create(
 176         model=MODEL,
 177         messages=[
 178             {
 179                 "role": "system",
 180                 "content": "Summarize the following conversation history into a concise summary. Keep all important facts, file paths, command results, and decisions. Be concise but don't lose critical details.",
 181             },
 182             {"role": "user", "content": old_text},
 183         ],
 184     )
 185     summary = summary_response.choices[0].message.content
 186
 187     print(
 188         f"[Compact] {len(old_messages)} 条旧消息 → 1 条摘要 (保留最近 {len(recent_messages)} 条)"

再看它怎么跑

压缩并非加分项，而是 Agent 完成长任务的关键能力。

演示命令

python agent/06-compact/agent-compact.py "请按步骤执行，不要合并成一个 shell 命令：1. 用 execute_bash 列出 agent 目录下的 Python 文件；2. 分别用 read_file 读取 agent/01-essence/agent-essence.py、agent/02-memory/agent-memory.py、agent/06-compact/agent-compact.py；3. 把三个文件的大致行数写入 compact-demo-report.txt。"
  • 默认演示阈值已调低到 COMPACT_THRESHOLD = 8，分步工具调用后可清晰看到 [Compact] 日志。
  • 压缩会保留 system prompt 与最近几条消息；如果遇到 tool 调用组，会向前扩展边界，避免切断工具响应。
  • 压缩本身也消耗 token，因此是一种工程折中，并非零成本能力。

Try It

自己试一轮

默认低阈值配合分步工具调用，是最直观的压缩演示方式。

  1. 先直接运行演示命令，观察默认低阈值如何触发压缩。
  2. 将 KEEP_RECENT 从 4 改为 2，对比当前任务衔接的变化。
  3. 观察压缩前后 messages 的结构变化，而不只查看日志。

Takeaway

这一讲会看懂什么

  • 理解为何更大的 context window 并非根本解决方案。
  • 能解释 COMPACT_THRESHOLD 与 KEEP_RECENT 的取舍。
  • 理解“保留要点、舍弃细节”是 Agent 的必要能力。

Key Points

三个核心要点

  • 压缩并非为了形式优雅，而是为了避免在真实任务中因上下文溢出而中断。
  • 最不能丢失的是 system prompt 与当前工作现场。
  • 将旧消息摘要化，本质是借助模型整理自身的历史。

Pitfalls

容易误解

  • 摘要过度会丢失关键路径与文件名。
  • recent window 过短会让 Agent 立即丢失工作上下文。
  • 只截断而不压缩，仍无法支撑复杂长任务。

上下文压缩函数

这就是分享里最值钱的 60 行：把旧历史折叠成摘要，把当前现场留下来。

看 GitHub 行号 
 129 def compact_messages(messages):
 130     """
 131     当 messages 过长时，把旧消息压缩成一段摘要。
 132
 133     压缩前: [system, msg1, msg2, ..., msg15, msg16, msg17, msg18, msg19, msg20]
 134     压缩后: [system, summary_of(msg1~msg14), msg15, msg16, msg17, msg18, msg19, msg20]
 135     """
 136     if len(messages) <= COMPACT_THRESHOLD:
 137         return messages  # 没超阈值，不压缩
 138
 139     print(
 140         f"\n[Compact] messages 数量 ({len(messages)}) 超过阈值 ({COMPACT_THRESHOLD})，开始压缩..."
 141     )
 142
 143     system_msg = messages[0]  # system prompt 永远保留
 144     old_messages = messages[1:-KEEP_RECENT]  # 需要被压缩的旧消息
 145     recent_messages = messages[-KEEP_RECENT:]  # 最近的消息保留原样
 146
 147     # 把旧消息拼成文本，交给 LLM 做摘要
 148     old_text = ""
 149     for msg in old_messages:
 150         role = (
 151             msg.get("role", "unknown")
 152             if isinstance(msg, dict)
 153             else getattr(msg, "role", "unknown")
 154         )
 155         content = (
 156             msg.get("content", "")
 157             if isinstance(msg, dict)
 158             else getattr(msg, "content", "")
 159         )
 160         if content:
 161             old_text += f"[{role}]: {content}\n"
 162
 163     # 调用 LLM 生成摘要
 164     summary_response = client.chat.completions.create(
 165         model=MODEL,
 166         messages=[
 167             {
 168                 "role": "system",
 169                 "content": "Summarize the following conversation history into a concise summary. Keep all important facts, file paths, command results, and decisions. Be concise but don't lose critical details.",
 170             },
 171             {"role": "user", "content": old_text},
 172         ],
 173     )
 174     summary = summary_response.choices[0].message.content
 175
 176     print(
 177         f"[Compact] {len(old_messages)} 条旧消息 → 1 条摘要 (保留最近 {len(recent_messages)} 条)"
 178     )
 179     print(f"[Compact] 压缩后 messages: {1 + 1 + len(recent_messages)} 条\n")
 180
 181     # 重新组装：system + 摘要 + 最近消息
 182     return [
 183         system_msg,
 184         {"role": "user", "content": f"[Previous conversation summary]: {summary}"},
 185         {
 186             "role": "assistant",
 187             "content": "Understood. I have the context from our previous conversation. Let me continue.",
 188         },
 189         *recent_messages,
 190     ]

再看它怎么跑

让大家看到压缩不是“加分项”，而是 Agent 长任务能不能活下来的生死线。

演示命令

python agent/06-compact/agent-compact.py "在当前目录下找到所有 Python 文件，统计每个文件行数并写入 report.txt"
  • 把阈值调小后，很容易在终端看到 `[Compact]` 日志。
  • 压缩会保留 system prompt 与最近几条消息，只把旧消息折叠成摘要。
  • 强调：压缩也是花 token 的，所以它是工程折中，不是白送能力。

Try It

自己试一轮

分享时把阈值调小，强制触发一次压缩，是最直观的讲法。

  1. 把 `COMPACT_THRESHOLD` 调到 8，制造一轮可见的压缩。
  2. 把 `KEEP_RECENT` 从 6 改成 4，比较当前任务衔接是否变差。
  3. 观察压缩前后 messages 的结构变化，不只看日志。

Takeaway

这一讲会看懂什么

  • 知道为什么更大的 context window 不是根治方案。
  • 能解释 `COMPACT_THRESHOLD` 与 `KEEP_RECENT` 的取舍。
  • 理解“记住要点、忘掉细节”是 Agent 的必要能力。

Share Track

分享只讲这 3 件事

  • 压缩不是为了优雅，是为了不在真实任务里死于上下文溢出。
  • 最不能丢的是 system prompt 和当前工作现场。
  • 旧消息摘要化，本质上是在用模型帮助自己整理历史。

Misread

容易误解

  • 摘要过度会丢掉关键路径和文件名。
  • recent window 太短会让 Agent 瞬间断片。
  • 只做截断不做压缩，依然扛不住复杂长任务。

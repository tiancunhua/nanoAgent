04. SubAgent 子智能体

当单个 Agent 需要同时承担架构、后端、前端工作时，应将部分任务委派给更聚焦的子代理。

Code First

将 subagent 封装为工具

独立 sub_messages 与禁止递归，是这段实现最值得关注的两点。

看 GitHub 行号 
 104 def subagent(role, task):
 105     """启动一个独立的 Agent 循环，拥有专属角色和独立上下文"""
 106     print(f"\n{'=' * 50}")
 107     print(f"[SubAgent:{role}] 开始: {task}")
 108     print(f"{'=' * 50}")
 109
 110     sub_messages = [
 111         {
 112             "role": "system",
 113             "content": f"You are a {role}. Be concise and focused. Only do what is asked.",
 114         },
 115         {"role": "user", "content": task},
 116     ]
 117     # SubAgent 不能再派 subagent（防无限递归），只用基础工具
 118     sub_tools = [t for t in tools if t["function"]["name"] != "subagent"]
 119
 120     for _ in range(10):
 121         response = client.chat.completions.create(
 122             model=MODEL, messages=sub_messages, tools=sub_tools
 123         )
 124         message = response.choices[0].message
 125         sub_messages.append(message)
 126
 127         if not message.tool_calls:
 128             print(f"[SubAgent:{role}] 完成\n")
 129             return message.content
 130
 131         for tc in message.tool_calls:
 132             fn = tc.function.name
 133             args = json.loads(tc.function.arguments)
 134             print(
 135                 f"  [SubAgent:{role}] {fn}({json.dumps(args, ensure_ascii=False)[:80]})"
 136             )
 137             result = available_functions[fn](**args)
 138             sub_messages.append(
 139                 {"role": "tool", "tool_call_id": tc.id, "content": result}
 140             )
 141
 142     return "SubAgent: max iterations reached"

Live Demo

再看它怎么跑

委派并不神秘，本质就是把另一个 Agent 也封装成工具。

演示命令

python agent/04-subagent/agent-subagent.py "创建一个 TODO 应用，包含 Python 后端和 HTML 前端"
  • 主 Agent 调用 subagent(...)，传入明确的角色与任务。
  • 子代理拥有独立的 sub_messages，不会复制主代理的全部上下文。
  • 子代理返回结果摘要，而非完整的内部历史。

Try It

自己试一轮

使用一个前后端双角色案例进行演示，委派的价值会立即显现。

  1. 将一个写 README 的任务改由文档子代理完成。
  2. 为子代理补充更具体的角色描述，观察输出稳定性的变化。
  3. 让主代理仅保留协调职责，避免同时承担所有实现细节。

Takeaway

这一讲会看懂什么

  • 理解 SubAgent 的关键在于独立上下文，而非额外启动一个模型实例。
  • 能解释为何应禁止子代理继续派生子代理。
  • 能将一个复杂任务拆解为主代理与子代理两类角色。

Key Points

三个核心要点

  • 委派的收益来自上下文收敛，并非单纯的并行化。
  • 角色 prompt 越具体，子代理越接近一个真正的岗位。
  • 返回摘要而非全量历史，是后续控制上下文成本的关键习惯。

Pitfalls

容易误解

  • 任务边界不清时，主代理与子代理会出现重复劳动。
  • 允许无限递归委派，成本与复杂度都会失控。
  • 子代理角色过于宽泛时，它只是换了名字的主代理。
